## Standardized specification

`standardized/notebook-manager-openapi.json`: the original, formatted (indented with 2 spaces; the original is minified, on one line). `standardized/notebook-manager-openapi.yaml` is the same specification in YAML, converted with yq 4.44.3 (the same content and order of properties, checked; see §6.4 of `docs/API-INTEGRATION-PROTOCOL.md` in RESTgym). The Swagger 2.0 version is converted from it (see below).

Changes from the original: none in the content (the same content, with the keys in the same order).

**Swagger 2.0 version** (`standardized/notebook-manager-swagger.json`, and `standardized/notebook-manager-swagger.yaml`, the same in YAML): converted from `standardized/notebook-manager-openapi.json` with hidi 3.10.2, the command-line tool of Microsoft's OpenAPI.NET (`mcr.microsoft.com/openapi/hidi:3.10.2.202608213`, `hidi transform -v 2.0 -f json`); its output is only formatted with yq 4.44.3, and its YAML version is converted with yq (see §6.4 of `docs/API-INTEGRATION-PROTOCOL.md` in RESTgym). Checked against the OpenAPI 3 version: the same 5 operations, with the same parameters (name, location, required), request bodies and response codes, and the same 2 schemas, in the same order; it passes the official validation. What the conversion changes: the server becomes `host: localhost:8080` and `schemes: [http]` (no `basePath`, which means `/`); the schemas become `definitions`; the request bodies become `body` (or form) parameters, and the media types of the request bodies and responses become `consumes` and `produces`.

The official validation passes: `standardized/validation.json` (2026-10, swagger-validator-v2 2.1.9) has no messages.
